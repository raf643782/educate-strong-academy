# Cloudflare — Operator Guide

Educate Strong uses two separate Cloudflare services:

1. **Cloudflare DNS** — controls where `educatestrong.com` resolves
2. **Cloudflare R2** — private object storage for course documents

These are in the same Cloudflare account but operate independently.

---

## Cloudflare DNS

### What it controls

DNS records for `educatestrong.com`. During the domain migration, the A and CNAME records will be pointed at Vercel.

### Access

1. Log in to https://dash.cloudflare.com with the Educate Strong account
2. Select the `educatestrong.com` zone

### Current state (pre-migration)

DNS currently points at the Wix website. Do not change any records until following `docs/domain-cutover-checklist.md` in full.

### Records that must be preserved during migration

| Record type | Purpose | What happens if deleted |
|---|---|---|
| MX records | Google Workspace email routing | All email to `*@educatestrong.com` stops |
| TXT records (SPF) | Email spam protection | Email may be marked as spam |
| CNAME `_domainkey.*` | DKIM email signing | Email may be marked as spam |
| TXT `_dmarc` | Email DMARC policy | DMARC failure; potential email deliverability issues |

**Critical**: Only the A record (root `@`) and the CNAME for `www` need to change when migrating to Vercel. All email-related records (MX, TXT, CNAME for `_domainkey`) must be left untouched.

### Records to add for Resend (email DNS pre-cutover)

Before go-live, add these DNS records to enable Resend transactional email:
- SPF TXT record for `educatestrong.com` (Resend will provide the exact value)
- DKIM CNAME records (Resend will provide the exact CNAME targets)
- DMARC TXT record at `_dmarc.educatestrong.com`

Get the exact values from the Resend dashboard → Domains → educatestrong.com → DNS records.

## Cloudflare R2

### What it stores

Private course documents (PDFs, workbooks, assessment materials) uploaded by admins through the Document Manager.

### Access

1. Log in to https://dash.cloudflare.com
2. Navigate to R2 Object Storage in the left sidebar
3. Open the bucket named as per `R2_BUCKET_NAME` env var on Render

### Bucket security

The bucket must be **private** — no public access. All reads and writes go through the backend API using presigned URLs:
- Upload: 5-minute presigned PUT URL generated by the backend
- Download: 2-minute presigned GET URL generated by the backend, only issued to enrolled learners

### R2 credentials

Four environment variables must be set on Render (see `docs/handover/environment-inventory.md`):
- `R2_ACCOUNT_ID`
- `R2_ACCESS_KEY_ID`
- `R2_SECRET_ACCESS_KEY`
- `R2_BUCKET_NAME`

To generate the access key:
1. Cloudflare dashboard → R2 → Manage R2 API Tokens
2. Create an API token with "Object Read & Write" permission for the specific bucket
3. Save the Access Key ID and Secret Access Key — the secret is only shown once

### Current state

The R2 integration code is fully implemented. Whether it works depends on whether the 4 env vars are set correctly on Render. If any are missing, the backend returns a "storage unavailable" error gracefully — no crash.

### Object naming

Objects are stored with the key pattern: `course-documents/{scope}/{uuid}{extension}`

### Costs

R2 has a generous free tier (10 GB storage, 10 million read operations/month). Course documents for an early-stage academy are well within this limit.
